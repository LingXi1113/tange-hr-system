## 2. 项目与目录

面向 AI 电商公司的招聘管理系统，主要招聘互联网研发、产品运营及销售商务人员。

```text
仓库根目录/
├── scripts/                      # Windows / Linux 启动脚本
└── projects/
    ├── backend/
    │   ├── run.py                # 服务入口
    │   ├── app.py                # Flask 工厂、初始化及 Blueprint 注册
    │   ├── config.py             # 从进程环境变量读取配置
    │   ├── common/               # 流转、解析、匹配、存储及权限逻辑
    │   ├── modules/              # 候选人、面试、人才库等 API
    │   └── tests/                # pytest
    ├── frontend/src/
    │   ├── pages/                # 各业务页面
    │   ├── components/           # AI 评估、助手、重复候选人确认等
    │   ├── services/             # API 请求
    │   └── utils/                # 业务刷新事件、本地演示 AI 等
    └── docs/                     # 功能记录与本文
```

技术栈：React 18 + TypeScript + Ant Design 5 + Vite 7；Python 3.12 + Flask 3；MongoDB。
所有业务记录与文件元数据都在 MongoDB，不使用 SQL 数据库。
开发环境可用本地文件存储，生产环境要求配置 OSS。
前端通常 5173，后端固定 8100；Vite 把 /api 与 /env 代理到后端。

旧电脑曾同时存在多个目录和一个旧发布克隆，不能按目录名字判断哪个最新。新电脑以 Git 克隆的 main 为基础，不要复制旧虚拟环境或 node_modules。

## 3. 必须保留的业务约定

以下是用户已确认的需求约定；跨页面行为仍应结合源码和实际数据验证，不能仅凭本文宣称全部验收通过。

### 候选人与招聘流转

- 新增候选人与导入简历合并为一个“新增候选人”入口，不删除该入口。
- 候选人界面新增/上传简历必须绑定真实职位；批量导入也必须选择职位。
- 人才库元数据的独立创建路径与候选人应聘上传不是同一个接口契约，不应无差别加限制。
- 上传选错文件时可删除当前简历、清理解析回填，或取消关闭新增窗口；过期的异步解析结果不得回填新文件。
- 业务复筛与直接进入面试是两条可选择渠道，业务复筛入口也可分配职位。
- 智能匹配是辅助操作，支持自选职位进行“投递职位匹配”，不得强制替换原有招聘流程。
- 面试官或 HR 都可“提交评价”；不要显示“HR代评价”。
- 评价提交后 HR 应能推进下一阶段或手动调整状态；不得重新引入“待 HR 确认”强制中间状态。
- 用户曾报告评价后按钮灰色、业务复筛按钮缺失。验证时需同时检查角色、应聘阶段、处理权、锁定和前端禁用条件，不能只改按钮文案。
- 工作台的数字应与目标列表使用一致统计口径，并精准跳转至对应子分类。
- 候选人变更后应联动刷新工作台与其他业务页；相关代码包括 businessDataEvents.ts。
- 工作台搜索先展示候选人下拉结果，点击结果才进入详情。
- 职位管理的阶段指标应打开相应业务页面，而非一律跳招聘流程看板。
- 新建职位不再要求选择面试轮次，沿用默认流程；面试职位下拉只显示职位名，不附部门。
- 超级管理员可赋予账号面试资格；必须同时验证后端鉴权和面试人列表。

### 人才库

- 保留文件夹侧栏；淘汰人员统一进入“已淘汰”，其他按职位归档。
- 客保到期仍未处理：已分配职位的归入职位文件夹，未分配的汇总由 HR 归档。
- 超级管理员管理文件夹增减；普通账号遵循既有可见范围和操作权限。
- 人才库列表应支持与候选人一致的简历查看入口，“已淘汰”人员也可进入详情查看资料与附件。
- 不把“已淘汰”误解成删除候选人主档或删除简历文件。

### 重复候选人判断

- 姓名、手机、邮箱均有值且规范化后全部一致：重复，进入已有主档合并/复用逻辑。
- 部分字段一致且存在关联：疑似重复，展示历史候选人，由 HR 确认同一人或非同一人。
- 疑似重复未确认前不得继续保存等后续操作；不能用 force 参数绕过。
- 确认同一人使用已有主档，非同一人才创建新主档；确认结果均记日志。
- 已实现签名确认令牌及快照校验；检查时关注令牌过期、资料变更、不同操作者及并发请求。
- 已存在主档编辑时，疑似同一人的路径仍有引导回已有主档的限制，不应当作任意两主档完整合并迁移工具。

## 4. 智能匹配与 AI：明确当前边界

本地演示版已包含岗位画像、人才库推荐、候选人 AI 评估展示与右下角助手入口。
岗位画像生成后可手动修改并保存；系统设置允许 HR 增减、调整匹配项，岗位类型有多套模板。

但这些模块不能一概称为已接入大模型：

- backend/common/screening.py：以配置项、关键词/同义词、学历、工作年限、业务特征等做可解释规则评分。
- backend/common/screening_config.py 与 modules/screening_api.py：匹配项配置和评估 API。
- frontend/src/utils/localAi.ts：包含画像构造、推荐排序和按问题类型返回摘要/追问的本地逻辑。
- CandidateAiAssistant.tsx、CandidateAiEvaluation.tsx：助手与评估界面。显示 AI 字样不等于调用外部模型。
- 简历解析的 AI 兜底是另一条路径：backend/common/resume_ai.py，按配置调用兼容服务。

不能虚构“已部署 embedding / 向量数据库 / RAG / 真实通用问答”。
后续若接入大模型，应设计统一后端服务、超时与失败回退、结构化输出校验、用量控制、简历隐私授权和证据引用。
必要项缺信息应提示待核实，不得当成真实经历或擅自推断。AI 不自动决定淘汰、录用或推进阶段。

BOSS 直聘数据接入曾被讨论，但不能据此认定官方授权接口、账号凭据或同步链路已经落地。实施前确认合法授权与可用接口，不绕过平台访问限制。

## 5. 简历解析链路与最近改动

主要文件：

- common/resume_parser.py：原生文本提取、字段识别、解析质量提示及 OCR / AI 调度。
- common/resume_work.py：工作/实习经历的独立规则。
- common/resume_ocr.py：RapidOCR 与 PDF 页面转图。
- common/resume_ai.py：可配置的 AI 兜底调用。
- common/resume_service.py：公开投递后的自动解析；只补候选人空字段。
- modules/candidate_api.py：预解析、候选人保存、简历上传等入口。
- tests/test_resume_parser.py、test_resume_work.py、test_candidate_job_binding.py：相关回归测试。

处理顺序：PDF / DOCX 原生文本提取 → 对图片或文本不足的 PDF 使用本地 OCR → 规则提取 → 缺字段/低质量时尝试配置的 AI 兜底 → 返回核对提醒。
前端显示的“置信度”是启发式提示，不是经统计评测的识别准确率。AI 不可用时保留规则结果并提醒人工核对。

2. PDF / DOCX / 图片处理和本地 OCR、可选 AI 兜底，支持失败提示。
3. 工作经历识别支持公司在日期前后、跨行公司名、扩展公司后缀、英文日期和 OCR 空格；区分教育、项目、客户及正文描述。
4. 无日期但可信的公司信息可以保留，提醒核对时间；不能承诺复杂简历绝无漏识别。

## 6. 新电脑安装与启动（Windows）

准备 Git、Python 3.12、可运行 Vite 7 的 Node.js（建议 Node 22.12+）及本机 MongoDB。
不要在生产库上调试或运行测试。

```powershell
git clone https://github.com/LingXi1113/tange-hr-system.git
cd tange-hr-system
git status --short
git log -1 --oneline
```

先确保 MongoDB 已启动。在仓库根目录的新 PowerShell 终端启动后端：

```powershell
$env:HRATS_ENV = 'development'
$env:MONGODB_URI = 'mongodb://127.0.0.1:27017'
$env:MONGODB_DATABASE = 'hr_ats_sandbox'
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-backend.ps1
```

脚本会在没有虚拟环境时创建 Python 3.12 环境并安装 requirements.txt。
在另一个终端回到仓库根目录：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-frontend.ps1
```

登录页：http://127.0.0.1:5173/#/login
后端健康检查：http://127.0.0.1:8100/api/health
开发模式有 Mock 用户，常用 hr-001；超级管理员以 seed.py 与登录页实际配置为准。生产必须禁用 Mock 登录并配置真实身份服务。

注意：

- 后端不会自动读取 .env；前端 vite.config.ts 也禁用了自动 envDir，需通过进程环境/启动脚本注入配置。
- 根目录启动脚本默认库名 hr_ats_sandbox，而直接 python run.py 的 Config 默认 hr_ats；必须统一库名，否则会看起来“数据丢了”。
- 修改环境变量或 Python 代码后，确认真正运行的后端进程已加载新配置；不要同时开两个 8100 后端。
- 新安装或迁移数据库时先关闭演示数据和阶段定时处理，再确认数据、索引、库名与附件路径，避免自动处理影响核对结果。

### 可选：启用本地 AI 简历兜底

不启用时仍可使用规则和 OCR。旧电脑用过 Ollama + qwen3:1.7b，程序和模型不在仓库内。
新电脑另行安装/下载后，指定实际路径，不要照搬旧电脑 D 盘：

```powershell
cd projects\backend
$env:MONGODB_DATABASE = 'hr_ats_sandbox'
powershell -NoProfile -ExecutionPolicy Bypass -File .\start-local-ai.ps1 -OllamaExe 'C:\实际安装目录\ollama.exe' -ModelsDirectory 'D:\实际模型目录' -Model 'qwen3:1.7b'
```

使用此脚本启动时，应先正常关闭普通后端，避免端口冲突。模型目录应与下载模型时一致。
脚本设置 AI 地址 http://127.0.0.1:11434/v1，超时 120 秒；CPU 速度视机器而定。
外部兼容服务通过 HRATS_RESUME_AI_BASE_URL、HRATS_RESUME_AI_MODEL、HRATS_RESUME_AI_API_KEY 等配置；密钥只放安全的运行环境，不提交 Git。
