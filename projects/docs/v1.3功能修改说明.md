# HR 招聘管理系统功能修改说明

> 修改周期：2026 年 8 月 26 日（上周三）至 2026 年 9 月 1 日  
> 适用版本：当前项目版本 v1.3   
> 文档用途：说明本周期已经完成的功能调整、业务规则和测试重点。

## 一、修改概览

本周期主要围绕“简历录入、招聘阶段、面试、Offer、客保规则、权限和操作体验”进行了完善，重点解决了以下问题：

1. 简历上传后无法稳定识别姓名、性别和工作经历。
2. 候选人阶段展示出现英文或乱码，流程进度不直观。
3. 面试安排与招聘阶段不一致，面试未完成时可以错误创建 Offer。
4. 面试不通过、Offer 拒绝后没有统一进入人才库。
5. 系统设置普通 HR 也可以修改，缺少超级管理员边界。
6. 招聘流程看板缺少导出能力，候选人列表存在链接和列布局问题。
7. 中文简历附件预览因文件名编码导致请求错误。

## 二、简历解析与候选人维护

### 2.1 新增候选人时自动解析

在“候选人 → 新增候选人”中，可以先上传 PDF 或 DOCX 简历。系统会在保存候选人前自动解析，并将结果回填到表单，HR 可以核对和修改后再保存。

目前支持辅助识别：

- 姓名；
- 性别（从简历正文中识别“男/女”等信息）；
- 手机号；
- 邮箱；
- 教育经历；
- 工作经历，包括公司、职位、开始时间、结束时间和工作内容。

### 2.2 解析规则调整

- 姓名提取增加了正文和常见简历格式的识别，不再把“简历”“个人优势”等标题误识别为姓名。
- 工作经历优先识别明确的公司信息；没有识别到公司时，不会根据任意文本猜测公司名称。
- 城市不再由简历解析结果自动预填，避免错误覆盖候选人城市。
- 解析失败不会阻止候选人创建，HR 可以手工填写或在详情页维护。

### 2.3 候选人详情维护

候选人详情页支持直接维护解析结果，包括：

- 基本信息、标签和备注；
- 多条教育经历；
- 多段工作经历；
- 简历附件的上传、预览、下载和删除；
- 解析状态和解析结果查看。

候选人列表中的姓名恢复为可点击链接，可以进入对应详情页。表格列增加了固定宽度、溢出省略和横向滚动处理，避免姓名、手机号和操作列重叠。

## 三、招聘阶段和流程展示

### 3.1 阶段进度条

候选人详情页增加横向阶段进度展示：

- 圆点表示阶段节点；
- 粗线表示已经完成的流程；
- 细线表示尚未进行的流程；
- 阶段名称显示在节点下方；
- 当前阶段使用突出颜色标识。

### 3.2 阶段名称中文化

候选人列表、候选人详情、面试和 Offer 相关页面统一使用中文阶段名称，例如：

| 原系统状态含义 | 页面显示 |
|---|---|
| 新进入招聘流程 | 待筛选 |
| HR 初筛通过 | 人力筛选 |
| 等待面试 | 待面试 |
| 正在面试 | 面试中 |
| 面试结论通过 | 面试阶段 |
| Offer 处理 | 录用通知 |
| 等待入职 | 待入职 |
| 完成入职 | 已入职 |
| 终止流程 | 已淘汰、已放弃、人才库 |

历史数据中的旧阶段仍保留兼容能力，但前端展示已转换为中文，不直接向用户显示英文状态编码。

### 3.3 候选人列表操作调整

候选人列表的“操作”列移除了“分配职位”按钮，避免在候选人总表中绕过应聘记录直接操作。职位关联和招聘阶段应以候选人的应聘记录为准；后端兼容接口仍保留，用于历史数据和已有业务调用。

## 四、客保与阶段锁定规则

### 4.1 HR 分配职位后的锁定

候选人被 HR 关联到职位并形成应聘记录后，按照当前规则进入招聘流程并产生客保锁定。未关联职位的候选人视为待筛选状态；关联职位后进入 HR 筛选相关阶段。HR 执行分配职位动作时，系统立即为该候选人启动 7 天客保锁定，并记录当前 HR、开始时间和结束时间。

阶段锁定由招聘阶段规则统一计算，锁定信息包括锁定人、开始时间、结束时间和当前状态。

### 4.2 阶段到期处理

阶段规则支持配置：

- 锁定天数；
- 未处理期限；
- 到期动作；
- 是否自动进入人才库；
- 是否自动提醒；
- 提前提醒天数；
- 期限计算基准。

当前演示规则重点包括：

| 阶段 | 锁定 | 未处理期限 | 到期处理 |
|---|---:|---:|---|
| 待筛选 | 5 天 | 无 | 保持当前状态 |
| HR 分配职位/人力筛选 | 7 天 | 无 | 保持当前状态 |
| 待面试 | 7 天 | 无 | 保持当前状态 |
| 面试中 | 7 天 | 无 | 保持当前状态 |
| 面试阶段 | 30 天 | 15 天 | 淘汰并进入人才库 |
| 录用通知 | 15 天 | 无 | 保持当前状态 |
| 待入职 | 45 天 | 90 天 | 放弃并进入人才库 |
| 已入职 | 长期 | 无 | 保持长期锁定 |

系统后台会扫描到期记录，执行阶段动作并写入操作日志；自动提醒失败时会记录后台异常，避免异常被静默吞掉。

## 五、面试流程调整

### 5.1 面试与招聘阶段绑定

面试记录必须建立在候选人的有效应聘记录上，并且当前阶段必须是允许安排面试的阶段。系统会校验：

- 职位和候选人是否一致；
- 当前阶段是否为面试相关阶段；
- 当前面试轮次是否符合职位配置；
- 是否已经存在重复或时间重叠的有效面试。

不能在 Offer、待入职、已入职、淘汰、放弃或人才库阶段继续安排面试。

### 5.2 面试安排页面

- 面试表单不再展示结束时间输入项，避免与当前产品要求不一致；
- 面试记录按候选人和职位应聘记录绑定；
- 面试完成后可以填写面试摘要、评价结论和面试反馈；
- 面试结论会写入阶段流转记录。

### 5.3 工作台面试时间线

工作台增加面试时间线，按日期展示当天需要处理的面试，便于 HR 和面试官集中查看近期安排、待处理面试和面试反馈任务。

## 六、面试、Offer 和人才库业务一致性

本周期对招聘流程的关键前置条件进行了统一：

```text
面试安排 → 面试完成并填写通过结论 → 面试阶段 → 创建/发送 Offer
```

具体规则如下：

1. 只有最后一轮面试已经完成，并且明确记录为“通过”，才允许创建、提交或发送 Offer。
2. 面试未完成、没有结论或结论不是通过时，不能创建 Offer。
3. 面试不通过时，应聘记录进入终止分支，同时候选人自动进入人才库。
4. Offer 被候选人拒绝时，应聘记录进入人才库，人才库来源记录为“Offer 拒绝加入”。
5. Offer 接受后才进入待入职，不能从普通面试阶段直接进入待入职。
6. 人才库写入采用幂等逻辑和候选人唯一约束，重复触发只保留一条人才库记录。

系统同时增加了历史演示数据修复逻辑，用于将原来不符合上述条件的演示候选人调整到正确阶段，并为可创建 Offer 的候选人补齐最后一轮通过面试记录。

## 七、系统权限和超级管理员

### 7.1 角色区分

新增并启用“超级管理员”角色，用于维护全局招聘配置。普通 HR 仍可以查看配置，但不能修改。

### 7.2 仅超级管理员可编辑的内容

- 流程模板配置；
- 面试评价模板；
- 系统参数；
- Offer 审批人配置；
- 字典和基础配置。

普通 HR 进入上述页面时显示只读提示和只读标识，后端接口也会拒绝普通 HR、面试官等角色的写入请求，不能仅依靠前端按钮隐藏来控制权限。

### 7.3 其他权限保持不变

候选人个人信息继续按照角色脱敏；招聘报表、操作日志、审批和入职等模块仍按既有角色范围开放。所有敏感操作继续写入操作日志。

## 八、附件预览修复

修复了中文简历文件名导致预览请求错误的问题。后端现在根据附件文件名正确设置 MIME 类型，并使用兼容中文文件名的响应头格式。

预览行为：

- PDF 以浏览器预览方式打开；
- 文件不存在或无权限时返回明确错误；
- 预览和下载继续执行业务权限校验；
- 不允许通过猜测附件地址绕过权限。

## 九、流程看板导出

招聘流程看板增加按职位导出功能，可将当前职位的候选人流程情况导出为 CSV 文件，用于线下汇报、核对和招聘进度分析。

导出内容以当前筛选的职位和流程数据为准，并沿用系统个人信息脱敏和导出留痕规则。

已完成的自动检查包括：

- 后端 Python 编译检查通过；
- 系统设置和模板权限测试通过；
- 简历解析相关测试通过；

## 十一、测试建议

建议按以下顺序验证本周期功能：

1. 使用超级管理员修改流程模板，确认普通 HR 只能查看不能保存。
2. 新增候选人并上传 PDF/DOCX，核对姓名、性别、手机号、邮箱、教育和工作经历。
3. 上传带中文文件名的 PDF，在候选人详情页点击预览。
4. 将候选人推进到面试阶段，安排对应轮次面试并填写摘要和结论。
5. 在面试未通过时检查候选人是否进入人才库。
6. 在最后一轮面试明确通过后创建 Offer；未完成或未通过时应被系统拦截。
7. 拒绝 Offer，确认候选人进入人才库且不会重复生成人才库记录。
8. 在工作台查看按日期排列的面试时间线。
9. 在招聘流程看板按职位导出 CSV，并核对导出内容。
