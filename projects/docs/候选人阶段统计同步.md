# 候选人阶段统计同步

更新日期：2026-10-26。

## 统一口径

- 候选人列表、分类统计和工作台来源数字共用 common/candidate_query.py 的筛选规则。
- GET /api/candidates?include_summary=1 在同一次请求中返回列表、总人数及 classification。前端不再分别请求两个接口后混合显示。
- 顶部“未处理 / 待定 / 人才推荐 / 待分配”的计数遵循当前主阶段、职位、部门、关键词、学历、来源和锁定筛选；子分类按钮彼此替换，不再重置主阶段。
- 点击分类后，卡片列表总人数等于该分类数字；翻页不会改变分类数字。
- 多次投递按候选人去重；卡片显示命中筛选的应聘记录，并携带 application_id 进入对应详情，而非显示另一条最新投递的阶段。
- 同一候选人可能在不同职位处于不同阶段，且待定标记、推荐来源可重叠，因此各分类不是互斥分组，不能相加当作总人数。
- 人才推荐沿用候选人页既有范围：内推、猎头、人才库、业务推荐；工作台和 source_group=talent_recommendation 同步采用这一规则。内推简历卡片仍可独立查看，不能将两张来源卡片简单相加。

## 刷新机制

- 新增、删除、导入、阶段推进等业务操作后，候选人页监听同页事件和跨标签页 storage 事件，刷新数字与列表。
- 返回窗口或页面重新可见时刷新；页面可见时每 15 秒补充一次后台刷新，覆盖其他账号或定时任务造成的变更。
- 后台刷新不反复隐藏列表；切换筛选时展示加载状态。
- 每次请求分配递增序号，丢弃迟到的旧响应，防止快速切换阶段后被旧数据覆盖。
- 加载失败或旧后端不支持组合统计时显示提醒和“—”，不以 0 或旧全局计数冒充当前结果。
- 从工作台进入当前已打开的候选人路由时，同步解析新的 URL 筛选条件。
