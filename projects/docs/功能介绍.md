# HR 招聘管理系统功能与使用说明

> 当前版本：项目代码快照 v1.3  
> 文档日期：2026-08-24  
> 文档用途：介绍当前已经实现的功能、页面入口、角色权限和日常操作方法。

## 1. 系统概览

本系统是一套覆盖招聘全流程的 HR 招聘管理系统，主要处理：

```text
招聘需求 → 职位发布 → 候选人/公开投递 → 简历筛选 → 面试 → Offer 审批与发送 → 入职资料 → 入职
                                      ↘ 淘汰 / 放弃 / 人才库
```

系统还提供简历解析与维护、候选人客保（简历锁定）、招聘阶段规则、站内通知、招聘报表、流程模板和操作日志等能力。

本说明按当前项目代码整理。当前版本已对申请、客保锁定、Offer、审批、入职和后台扫描加入唯一索引、版本校验或任务租约；实际操作中如遇到“状态已变化”“版本冲突”等提示，应刷新页面后重新确认当前数据再操作。

## 2. 登录、启动与测试环境

### 2.1 浏览器访问

开发环境通常访问：

- 前端：`http://127.0.0.1:5173/#/login`
- 后端健康检查：`http://127.0.0.1:8100/api/health`

前端通过 Vite 将 `/api` 请求代理到 8100 端口。正式环境应使用实际部署地址，不应把浏览器直接配置到后端地址。

### 2.2 本地启动

先确保 MongoDB 已启动，再分别启动后端和前端：

```powershell
# 后端
cd projects/backend
.venv\Scripts\python.exe run.py

# 前端（另开终端）
cd projects/frontend
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort --clearScreen false --cors
```

开发环境默认使用：

- MongoDB：`mongodb://127.0.0.1:27017`
- 数据库：`hr_ats`
- Mock 登录：开启
- 演示数据：开启

如果登录后看不到演示数据，通常是启动环境变量未开启 `HRATS_SEED_DEMO_DATA=1`，或连接的 MongoDB 数据库不是当前开发库。

### 2.3 开发环境测试账号

登录页可使用 Mock 登录；登录后也可以通过右上角角色切换查看不同角色的页面和权限。

| 用户 ID | 角色 | 主要用途 |
|---|---|---|
| `hr-001`、`hr-002` | HR | 全部招聘管理、配置和报表功能 |
| `screen-001` | 业务复筛人员 | 查看候选人并参与业务筛选 |
| `interviewer-001` | 面试人员 | 参与面试和评价 |
| `org-001` | 组织统筹审批人 | Offer 组织统筹审批 |
| `gm-001` | 总经理 | Offer 总经理审批 |
| `chairman-001` | 董事长 | Offer 董事长审批 |
| `offer-001` | Offer 发送专员 | 查看审批结果并处理 Offer |
| `ssc-001` | SSC 入职办理人员 | 维护入职资料和办理入职 |

生产环境应关闭 Mock 登录和演示数据，使用真实平台身份认证；生产环境还必须配置外部 MongoDB 和对象存储 OSS。

## 3. 角色与权限

系统权限由后端接口控制，页面菜单只是入口控制，不能替代后端权限校验。

|---|---|---|

| 面试人员 | 候选人、流程看板、面试相关查看/参与 | 个人信息脱敏 |
| 组织统筹审批人 | 审批中心、候选人和 Offer 相关查看 | 个人信息脱敏 |
| 总经理 | 审批中心、候选人和 Offer 相关查看 | 个人信息脱敏 |
| 董事长 | 审批中心、候选人和 Offer 相关查看 | 个人信息脱敏 |
| Offer 发送专员 | 审批中心、Offer 相关处理和查看 | 个人信息脱敏 |
| SSC | 入职资料、候选人和 Offer 相关查看 | 个人信息脱敏 |

以下页面目前属于 HR 管理范围：招聘报表、流程模板配置、面试评价模板、系统参数与审批人、操作日志。Offer 审批中心对 HR、组织统筹审批人、总经理、董事长和 Offer 发送专员开放；入职资料对 HR 和 SSC 开放。

## 4. 工作台

入口：`工作台`（`/workbench`）。

工作台用于快速了解当前招聘情况，通常包括：

- 需求、职位、候选人、面试、Offer、入职等概览统计；
- 招聘漏斗和各阶段人数；
- 待处理任务、近期活动和异常/逾期提醒；
- 未读站内通知入口。

工作台是汇总页，具体处理应进入对应业务模块完成。

## 5. 招聘需求管理

入口：`招聘需求`（`/requirements`）。主要由 HR 使用。

### 5.1 新建和维护需求

1. 点击“新建需求”。
2. 填写需求名称、所属部门、招聘人数、需求类型、优先级和岗位要求。
3. 可选择一个已有职位进行关联；保存后该职位会同步显示在需求详情的关联职位中。
4. 可继续填写截止日期、负责人、原因和备注。
5. 保存后需求处于草稿状态，可继续编辑。
6. 信息确认无误后提交。

提交需求至少需要：需求名称、部门、人数、需求类型、优先级和岗位要求。

### 5.2 需求状态

| 状态 | 含义 | 可执行动作 |
|---|---|---|
| 草稿 | 正在编辑 | 提交 |
| 待确认 | 已提交，等待确认 | 确认、关闭 |
| 招聘中 | 需求生效 | 暂停、完成、关闭 |
| 已暂停 | 暂停招聘 | 恢复、关闭 |
| 已完成 | 招聘完成 | 无 |
| 已关闭 | 需求关闭 | 无 |

需求详情页可以查看关联职位、候选人数量、阶段分布和需求操作日志。

关联职位时，系统会校验职位是否存在；已经关联其他招聘需求的职位不能重复关联。职位也可以在职位编辑页直接维护所属招聘需求。

## 6. 职位管理与公开投递

入口：`职位管理`（`/jobs`）。主要由 HR 使用。

### 6.1 新建职位

填写职位名称、职位编码、部门、工作地点、职位类型、职级、汇报对象、招聘人数、薪资范围、岗位描述、任职资格、技能要求、发布渠道和关联需求。

职位编码需要保持唯一。已有职位可以复制，用于快速创建相近职位。

### 6.2 配置面试轮次

在职位中可以配置面试轮次，支持：一面、二面、三面、HR 面试、复试。多轮职位会按配置顺序推进；历史职位仍兼容旧的一面、二面、三面、HR 面试等阶段。

### 6.3 职位状态

| 状态 | 可执行动作 |
|---|---|
| 草稿 | 提交发布 |
| 待发布 | 发布、退回草稿 |
| 招聘中 | 暂停、关闭 |
| 已暂停 | 恢复、关闭 |
| 已关闭 | 无 |

### 6.4 公开职位页面

职位发布后可以生成公开访问链接，页面入口形式为：

```text
/public/job/{职位公开 token}
```

候选人可以在公开页面查看职位并投递。公开投递需要姓名、有效的中国大陆手机号、隐私同意；邮箱为可选但填写时必须有效。可以同时上传简历，投递来源记录为网站。

公开投递上传简历后，系统会自动提取 PDF/DOCX 中的姓名、手机号、邮箱和教育经历，并只补充候选人当前为空的基础字段；城市不参与自动解析。解析失败不会影响投递成功，HR 可在候选人详情页查看失败状态并人工维护。图片简历当前保留附件，但自动解析结果为失败。

## 7. 候选人和简历维护

入口：`候选人`（`/candidates`）。

### 7.1 候选人列表

支持按关键词、性别、城市、来源、当前阶段、锁定状态等条件查询，也可以结合标签、人才库分类维护候选人。

非 HR 角色看到的手机号和邮箱会脱敏；这属于后端返回数据的权限控制，不是页面隐藏。

### 7.2 新建候选人

可以手工新建候选人，也可以通过公开投递、职位关联或简历上传产生候选人。录入姓名、性别、手机号、邮箱、城市、来源、标签和备注。

系统会按手机号、邮箱检查重复候选人。出现相似候选人提示时，应先确认是否为同一人；确需建立新记录时可以选择强制创建。

系统会将手机号和邮箱规范化后建立候选人身份键，并由 MongoDB 唯一索引处理并发新增、导入和官网投递。强制创建的重复记录会标记为人工确认豁免，不会破坏正常候选人的唯一保护；历史重复数据保留原记录并继续通过业务提示处理。

### 7.3 简历上传、解析和编辑

在候选人列表点击“新增候选人”时，可以先上传 PDF/DOCX 简历。系统会先临时解析文件并自动回填姓名、手机号、邮箱和教育经历，城市不参与自动解析；HR 核对或修改后点击“保存”。候选人创建成功后，原简历会自动作为附件关联到该候选人，并再次记录解析状态。

解析仅用于辅助录入，不能替代人工核对；扫描图片、加密 PDF 或无法提取文本的文件会提示人工填写。候选人详情页的“简历附件”仍支持后续补传和重新解析。

候选人详情页可以：

- 上传简历并触发解析；
- 查看解析状态和解析后的姓名、手机号、邮箱、教育经历；
- 直接编辑解析结果；
- 增删教育经历和工作经历；
- 维护候选人基本资料、标签和备注；
- 编辑保存带有候选人版本校验。若其他人员已先修改，系统会提示版本冲突，刷新详情后再提交，避免旧页面覆盖新数据；
- 上传、查看、下载和删除附件（权限允许时）。

支持的通用文件类型包括 PDF、Word、Excel、PowerPoint、文本、CSV 和常见图片，单文件默认不超过 20 MB。生产环境文件使用 OSS，开发环境未配置 OSS 时使用本地文件存储。

### 7.4 关联职位和申请记录

在候选人详情页可以把候选人分配到职位。系统会检查：

- 职位是否处于接受候选人的状态；
- 候选人是否已经申请该职位；
- 候选人是否仍处于其他职位的有效客保锁定期。

候选人详情还可以查看该候选人的申请、阶段、锁定信息、面试、Offer 和操作日志。

### 7.5 解锁和删除

HR 可以在有业务依据时强制解锁，但必须填写解锁原因，系统会记录操作日志。删除候选人需要二次确认，并会级联清理相关个人资料和文件元数据；生产环境执行前应确认删除对象。

## 8. 招聘流程看板与客保规则

入口：`招聘流程看板`（`/pipeline`）。看板按职位/需求和招聘阶段展示候选人卡片，包含停留天数、当前锁定状态和可执行动作。

### 8.1 当前默认阶段

| 阶段 | 说明 |
|---|---|
| 新简历 | 候选人刚进入招聘流程 |
| 待筛选 | 等待业务或 HR 筛选 |
| HR 筛选通过 | 已通过 HR 筛选 |
| 待面试 | 等待安排面试 |
| 面试中 | 已进入面试过程 |
| 面试通过 | 面试结论通过，准备进入 Offer |
| Offer 中 | 进入录用/Offer 环节 |
| 待入职 | 候选人已接受录用，等待入职 |
| 已入职 | 完成入职 |
| 淘汰、放弃、人才库 | 终止或转入人才库的结果状态 |

还可以通过流程模板加入笔试、测评、背调、复试或自定义阶段。

### 8.2 客保规则（当前版本）

简历进入某一招聘阶段后，系统按阶段启动锁定天数；锁定期间原则上不能被分配到其他职位。阶段发生变化时，旧阶段锁定结束，新阶段按新规则重新计时。

| 招聘阶段 | 锁定天数 | 未处理期限 | 到期动作 |
|---|---:|---:|---|
| 新简历 | 0 | 0 | 无 |
| 待筛选 | 5 | 0 | 无 |
| HR 筛选通过 | 0 | 0 | 无 |
| 待面试 | 7 | 0 | 无 |
| 面试中 | 7 | 0 | 无 |
| 面试通过 | 30 | 15 | 自动淘汰并进入人才库 |
| Offer 中 | 15 | 0 | 无 |
| 待入职 | 45 | 90 | 自动放弃并进入人才库 |
| 已入职 | 9999 | 0 | 视为长期锁定 |

规则含义：

- 新候选人进入流程时从“新简历”开始；
- “待筛选”阶段默认锁定 5 天；
- 面试通过后 30 天内保持锁定；如果 15 天没有继续处理，系统按规则淘汰并进入人才库；
- Offer 中默认锁定 15 天；
- 待入职默认锁定 45 天；如果以入职计划日期为基准超过 90 天仍未办理，系统自动转为放弃并进入人才库；
- 阶段规则到期前会产生提醒，具体提醒时间由阶段规则中的“提前提醒天数”控制；
- HR 可以在流程模板中按招聘阶段调整锁定天数、未处理期限、到期动作、是否进入人才库、是否自动提醒和提醒提前天数。

阶段规则后台任务默认周期性检查到期记录并生成提醒/到期动作。规则调整后，新进入阶段的记录按新配置执行；已经发生的业务记录应以详情页显示的锁定和阶段时间为准。

### 8.3 看板操作

1. 选择职位或需求，定位候选人卡片。
2. 查看当前阶段、停留天数、锁定结束时间和提醒信息。
3. 选择允许的下一阶段并填写必要原因。
4. 涉及面试的阶段，系统会检查是否有面试安排和评价反馈。
5. 不能跳过必经阶段；淘汰、放弃、进入人才库属于终止分支。
6. 操作成功后重新查看候选人详情，确认申请状态、锁定记录和日志均已更新。

## 9. 面试管理

入口：`面试管理`（`/interviews`）。

### 9.1 安排面试

HR 在真实的候选人申请记录上创建面试，填写：

- 面试轮次：一面、二面、三面、HR 面试或复试；
- 面试类型：现场、视频、电话；
- 开始时间和结束时间；
- 地点或视频链接；
- 面试官姓名、联系方式；
- 评价模板和备注。

多轮职位必须按职位配置的下一轮创建，不能随意跨轮次。系统会检查同一候选人的有效面试时间是否重叠。

### 9.2 面试状态和反馈

面试状态包括待安排、已邀约、已确认、已完成、已取消和改期等状态。改期会保留改期记录。

面试完成前需要填写评价反馈，或明确选择跳过评价。反馈支持按评价维度打 1—5 分，并填写结论、评价意见、风险、建议薪资和评价人。

结论处理：

- 通过：单轮职位进入“面试通过”；多轮职位进入下一面试轮次，全部完成后进入“面试通过”；
- 待定：保留当前阶段，不自动推进；
- 不通过：必须填写原因，申请进入淘汰状态。

## 10. Offer、录用审批与发送

入口：`Offer 管理`（`/offers`）、`录用审批`（`/approvals`）。

### 10.1 创建和维护 Offer

通常在候选人面试通过后创建 Offer，填写：部门、职位、薪资、计划入职日期、有效期、工作地点、试用期、合同期限、福利和备注。

Offer 状态流程：

```text
草稿 → 待发送 → 已发送 → 已接受 / 已拒绝 / 已过期 / 已撤回
```

提交 Offer 后会触发审批；发送成功后申请进入 Offer 环节；候选人接受后进入待入职。Offer 到期会根据有效期进行过期处理。

### 10.2 审批链

当前审批链按以下顺序执行：

```text
组织统筹审批 → 总经理审批 → 董事长审批
```

HR 在“系统参数与审批人”中维护审批人。审批人进入“录用审批”后只能处理分配给自己的当前节点：

- 同意：进入下一个审批节点；最后一个节点同意后完成审批；
- 驳回：必须填写驳回原因；
- 审批中心会显示当前节点、待审批人、截止时间、剩余天数和逾期状态。

Offer 发送专员可以访问审批/Offer相关页面并处理发送工作，但当前审批链的核心节点仍是组织统筹、总经理和董事长。

### 10.3 Offer 附件

HR 可以上传 Offer 附件，具备权限的角色可以查看、预览或下载。附件访问由后端按业务类型和角色控制，不能通过猜测文件地址绕过权限。

## 11. 入职资料

入口：`入职资料`（`/onboarding`），HR 和 SSC 使用。

候选人接受 Offer 后会进入待入职并生成入职记录。默认资料清单包括：身份证件、学历证明、离职证明、体检报告、银行卡信息、入职登记表；HR 可以在系统参数中维护默认清单。

操作步骤：

1. 打开对应候选人的入职记录。
2. 点击开始办理，记录进入办理中。
3. 逐项维护资料状态：待提交、已提交、已核验、已驳回，并填写备注。
4. 所有资料核验通过后点击完成入职。
5. 系统将申请阶段改为“已入职”，入职记录改为已完成。

未全部核验通过时不能完成入职。计划入职日期来自已接受的 Offer。

## 12. 人才库

入口：`人才库`（`/talent-pool`）。

功能包括：

- 手工加入候选人或批量加入；
- 维护人才库分类、标签、来源、进入原因、推荐职位和最近联系日期；
- 激活、归档和批量操作；
- 查看候选人历史招聘记录；
- 将人才库候选人重新激活到职位，重新执行职位接受状态、重复申请和客保锁定检查；
- 查看或导出权限允许范围内的数据。

阶段到期、淘汰、Offer 拒绝等业务结果可以按规则自动进入人才库。人才库中同一候选人的有效记录需要保持唯一，避免重复维护。

## 13. 站内通知和我的任务

入口：`站内通知`（`/notifications`）、`我的任务`（`/tasks`）。

通知用于提示：

- 新候选人进入；
- 面试安排、面试提醒和待反馈；
- Offer 即将到期；
- 审批即将到期或已逾期；
- 招聘需求逾期；
- 阶段客保规则即将到期或已到期；
- 候选人长期未处理。

用户可以打开通知跳转到关联业务页面，支持单条已读和全部已读。我的任务集中展示当前用户需要处理的事项，例如待审批、待反馈和待办理的流程任务。

## 14. 招聘报表

入口：`招聘报表`（`/reports`），HR 使用。

当前提供：

- 需求报表：需求总量、招聘中、已完成、逾期及明细；
- 招聘漏斗：各招聘阶段候选人数量；
- 渠道分析：不同来源的候选人、申请、面试、Offer、入职数量及转化率；
- 招聘周期：招聘、筛选、面试、Offer 到入职等平均耗时。

报表可按职位、部门、负责人、来源、需求状态和时间范围进行筛选。报表中的个人信息仍受角色脱敏规则限制。

## 15. 系统设置

入口：`系统设置`，仅 HR 使用。

### 15.1 流程模板配置

入口：`流程模板配置`（`/pipeline-template`）。

HR 可以新建或编辑招聘流程模板，配置：

- 阶段顺序和阶段名称；
- 必经阶段、可跳过/可选阶段；
- 阶段锁定天数；
- 未处理期限；
- 到期动作：无、淘汰、放弃、进入人才库；
- 是否自动进入人才库；
- 是否自动提醒、提前提醒天数；
- 期限计算基准：进入阶段时间或计划入职日期。

模板应在招聘业务启用前确认。修改模板后，建议新建测试申请验证阶段顺序、锁定天数和到期动作。

### 15.2 面试评价模板

入口：`面试评价模板`（`/eval-template`）。

HR 可以维护评价模板、评价维度、适用轮次和关联职位。安排面试时选择模板，面试官按维度填写 1—5 分、结论和意见。

### 15.3 系统参数、审批人和字典

入口：`系统参数与审批人`（`/settings`）。

可维护：

- 默认锁定天数；
- 默认入职资料清单；
- Offer 审批人：组织统筹、总经理、董事长、Offer 发送专员；
- 来源渠道；
- 需求类型；
- 职级；
- 淘汰原因；
- 人才库分类；
- 职位类型。

### 15.4 操作日志

入口：`操作日志`（`/audit-logs`）。

可按业务类型、关键词等条件查看候选人、申请、面试、Offer、审批、入职、导出等操作记录。涉及强制解锁、状态变化、删除和审批的操作都应通过日志追溯。

## 16. 推荐的完整业务操作顺序

1. HR 创建招聘需求并提交确认。
2. 在需求下创建职位，配置职位信息、发布渠道和面试轮次。
3. 发布职位，或复制公开职位链接给候选人投递。
4. 在候选人模块检查重复、上传/解析简历并修正解析结果。
5. 将候选人关联到职位，确认客保锁定状态。
6. 在流程看板推进筛选阶段，按阶段规则安排处理。
7. 安排面试，完成面试反馈并应用通过/待定/不通过结论。
8. 面试通过后创建 Offer，提交组织统筹、总经理、董事长审批。
9. 审批完成后发送 Offer，跟踪接受、拒绝或过期结果。
10. 候选人接受 Offer 后，在入职资料中逐项收集和核验材料。
11. 全部材料核验通过后完成入职，申请进入“已入职”。
12. 对淘汰、放弃或长期未处理的候选人，按需要进入人才库并维护后续联系。

## 17. 常见问题与排查

### 17.1 页面没有数据

检查后端健康地址是否返回成功，再确认前端代理是否指向 8100 端口，以及登录用户是否有对应模块权限。

### 17. 看不到手机号或邮箱

这是非 HR 角色的隐私脱敏规则。需要 HR 按业务授权查看，不应通过接口或文件地址绕过权限。

### 17. 候选人不能分配到职位

依次检查职位是否招聘中、是否已经申请过该职位、是否还处于其他职位的客保锁定期。确需处理时由 HR 在候选人详情页按业务原因强制解锁。

### 17. 阶段不能推进

检查是否跳过了必经阶段，面试阶段是否已经安排面试并提交反馈，Offer/入职阶段的前置业务记录是否完整。

### 17. 入职不能完成

检查清单中的每一项是否都已经是“已核验”。仅上传或提交资料不能代替核验。

### 17. 接口报错

后端统一返回 `{code, msg, data}`：

- `code=0`：成功；
- `1002`：数据不存在；
- `1003`：当前状态不允许操作；
- `1004`：重复数据；
- `1005`：客保锁定；
- `1006`：无权限；
- `1007`：状态或版本冲突；
- `5001`：MongoDB 不可用。

优先按 `msg` 处理；状态或版本冲突时刷新页面，重新确认当前阶段后再操作。

## 18. 当前版本边界

- 本文介绍的是当前代码版本已经提供的功能，不代表后续规划功能已经上线。
- 核心业务已加入数据库唯一约束、乐观锁和后台任务租约；跨服务消息队列、分布式锁监控和更深入的高并发压测仍属于后续增强项，当前操作仍应以页面最新数据为准。
- 开发环境可以使用 Mock 登录和本地文件存储，不能直接作为生产部署方案。
- 生产环境必须关闭 Mock 登录和演示数据，配置非本机 MongoDB、OSS、真实平台身份认证，并修改生产密钥。
- 涉及候选人隐私、强制解锁、删除、导出、Offer 和审批的操作，应遵循公司授权流程，并通过操作日志留痕。
