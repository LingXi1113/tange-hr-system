# 候选人投递分析与面试联动

更新：2026-10-26。

## 页面入口

- 候选人详情增加“简历 / 投递分析”页签。投递分析显示投递、推荐、面试三类统计卡片，按每次应聘展开时间线，支持一键展开/收起。
- 顶部“次数 · 当前职位”下拉列出每次投递的职位、状态、日期、负责人和来源，支持同一候选人在同一职位的多次历史投递，不仅按职位去重。
- 切换时在 URL 保存 application_id，刷新、打开流程看板或面试列表返回详情时仍定位到相应应聘记录。

## 不再遗漏待安排人员

进入一面只代表应聘阶段改变，不代表已经确定面试时间、面试官。不能凭空创建面试安排。

面试管理增加“全部面试 / 待安排面试 / 面试记录”页签：

1. 已进入当前面试阶段且没有本轮场次的记录，显示在待安排列表。
2. 点击安排时绑定准确的 candidate_id、job_id、application_id 及当前轮次。
3. 安排后从待安排列表移出，进入面试记录；取消本轮面试后回到待安排。
4. 已完成上一轮，但当前轮次尚未安排的，仍显示为当前轮待安排；历史 next_action 不覆盖这个事实。

新增只读 API：GET /api/interviews/pending-applications，供 HR / 超级管理员使用，支持职位、候选人、应聘记录、轮次和分页筛选。现有 /api/interviews 仍只返回真实场次，不混入虚拟面试 ID。

## 看板与刷新

- 招聘流程看板默认“全部职位”，也可筛选单个职位；无 job_id/requirement_id 时后端返回跨职位合并阶段列。
- 模板调整后，历史应聘阶段没有对应模板列时补充展示列，不修改历史数据，也不让卡片消失。
- 推进时重新加载当前卡片对应职位的阶段选项，不把其他职位的模板当成可流转目标。
- 候选人、看板、面试管理订阅业务变更与窗口重新激活事件，避免已打开页面长期停留在旧数据。

## 数据口径

- 投递数按 applications 条数统计；已归档/淘汰记录仍保留。
- 最高到达阶段包含当前阶段、流转来源/目标及面试轮次，不能因淘汰或回退而丢失历史最高阶段。
- 推荐次数按进入业务复筛统计，通过按该次业务复筛后推进统计。
- 面试场次排除已取消记录；评价通过率分母为已完成且有有效非跳过评价的场次。
- 每次投递时间线包含创建、阶段流转、面试安排、评价，不将其他投递的场次混到当前记录。
- 操作日志按业务类型与 ID 配对查询，避免不同集合自增 ID 相同而混入其他候选人的日志。
